# TikTok LIVE community plugin (`tiktok-live`)

## Changes made during implementation (2026-11-05)

The plan below is the approved version. These points changed once the code met real data:

- Chat uses cookies, not Euler OAuth. Euler's OAuth token exchange requires a client secret
  kept on a server, which a public plugin ZIP cannot hold. 0.1.x had a sign-in page on
  127.0.0.1 with sign-in and sign-out blocks. After 0.1.1 the user asked for chat to be set
  up in the plugin settings instead. The `sessionid` and `tt-target-idc` cookies are now
  secret settings in the Chat (BETA) tab, and the Euler key has its own Euler Stream tab.
  Both blocks and the page are gone.
- Sending chat does not need a connection. A short-lived client with the cookies checks that
  the streamer is live, looks up the room and posts, so it works with either transport.
  Measured on 2026-11-05: Euler refuses the post without its Webcast Premium add-on, which
  the free trial does not include.
- No gift catalogue at connect time. `enableExtendedGiftInfo` and the gift list need a Euler
  Business plan (measured). Gifts are learned as they arrive; refresh gift list loads the
  full list for Business keys.
- One palette group. At the user's request every block declares only the category
  "TikTok LIVE" and no subcategory, so the Studio shows one group with 41 blocks.
- The landing page lives in `site/`, made with the impeccable, design-taste-frontend,
  high-end-visual-design and gpt-taste skills.
- The plugin is licensed AGPL-3.0-only because it bundles AGPL-3.0 code.
- The manifest is generated by `build/manifest.mjs`.

## Approved plan

Plan for a new official community plugin in `plugins/tiktok-live/`.

## Context

OSC Flow Studio has no TikTok LIVE integration. Tools such as TikFinity, Streamer.bot
(through TikFinity), Social Stream Ninja and AxelChat already react to LIVE events, and
streamers expect the same inside the Studio: triggers for joins, battles, gifts (by coins
and by specific gift), plus actions and inputs, and ideas those tools do not offer.

Constraints from the user:
- Plugin entirely in English (manifest, README inside the ZIP, logs).
- Triggers must behave identically regardless of host locale/timezone.
- Transport: direct connection **and** a TikFinity local bridge.
- Chat sending: opt-in **BETA**, browser-tab sign-in, remote kill switch, deprecation
  behaviour when disabled.
- Third-party software must be credited in the plugin settings and plugin details, with
  repository links.
- Never commit; hand over commit messages (see CLAUDE.md).

## Host contract (verified in code)

- Plugin = `plugins/<id>/plugin/` (the ZIP). `manifest.json` with `apiVersion: 2`,
  `permissions`, `entry: "index.mjs"`, default export `{ activate(ctx), deactivate() }`.
  Config save = deactivate + activate. Runs on the backend's Node 22 with
  `--permission --allow-fs-read=<pluginDir>/*`: no bare npm imports, no files, no child
  processes; sockets, `fetch` and global `WebSocket` work.
- `ctx`: `log`, `config.get()`, `secrets.get/set/delete` (only persistence), `emitTrigger(kind,
  payload)` (host wraps as `{triggeredAt, integration, kind, actorId, actorDisplayName,
  metadata}`), `registerAction(name, handler(data) -> object)`, `setStatus`,
  `setResource(key, items)`, `signal`.
- `matchFields` modes: equals, contains, regex, any, gt, gte, lt, lte; `eventField` is a path
  into the raw payload; empty node value matches all; numeric modes fail closed.
- `validate.mjs` scans every `.mjs/.js/.cjs` under `plugin/` (vendored code included) for
  `node:net/tls/http/https/dns/dgram`, `fetch(`, `new WebSocket(` -> `network` must not be
  `none`. Limits: 20 MB zip, 500 files. Labels are raw strings (no i18n).
- Patterns to mirror: `plugins/livepix/plugin/index.mjs` (lifecycle, status, persistence
  queue), `plugins/giggle-puck/plugin/index.mjs` (`startRuntime(ctx, overrides)` injection,
  `setResource`), `plugins/giggle-puck/tests/manifest.test.mjs` (handler/output contract),
  `plugins/livepix/tests/helpers/dashboard.mjs` (fake ctx + `until`).
- Host docs: `osc-flow-studio/examples/plugins/README.md`, `oauth-connector` example
  (device-flow pattern, secrets as separate vault keys, refresh, sign-out).

### LiveSource contract
`start()`, `stop()` (idempotent), `onEvent(cb({name, data, transport}))`,
`onState(cb({state: connecting|connected|waiting|disconnected|error, reason, attempt}))`,
`fetchGifts()`, `fetchRoomInfo()`, `fetchIsLive()`, `sendChat(text)`, `capabilities`.
`startRuntime(ctx, { createSource, timers, now, fetchImpl })` lets tests inject fakes.

### `direct`
- `TikTokLiveConnection(uniqueId, { signApiKey?, processInitialData, fetchRoomInfoOnConnect:
  true, enableExtendedGiftInfo, webClientOptions/webConfigOverrides })` with fixed English
  client params (`app_language: "en-US"`, `webcast_language: "en"`, `browser_language`), so
  `giftName` is stable. Exact option names verified against the pinned source in Phase 2.
- Reconnect backoff `reconnectMinSeconds..reconnectMaxSeconds` (5 s..300 s, doubling). A 429 /
  rate-limit error floors the wait at 60 s and surfaces "Euler Stream rate limit; add an API
  key" in status. Offline host: state `waiting`, poll `fetchIsLive()` every
  `offlinePollSeconds` (60). All timers cleared on `stop()`; `ctx.signal` aborts fetches.
- Subscribes to every `WebcastEvent`; handlers never throw (log once per event name).

### `tikfinity`
Global `WebSocket` to `bridgeUrl` (default `ws://localhost:21213/`), `{event, data}` mapped
1:1, backoff 2 s..30 s, `fetchGifts`/`sendChat` unsupported (gift dropdown stays empty,
manual gift id field is the fallback).

### Normalisation (locale independence)
- Ordered fallbacks per field because v2 payloads are protobuf-shaped and TikFinity sends
  flattened v1 names: `read(data, ["giftDetails.diamondCount", "diamondCount", ...])`.
- Canonical user block on every actor-bearing kind: `userId`, `uniqueId`, `nickname`,
  `profilePictureUrl`, `isModerator`, `isSubscriber`, `followStatus`
  (`none|follower|friend`), `gifterLevel`, `teamMemberLevel`, `topGifterRank`,
  `actorId = userId`, `actorDisplayName = nickname || uniqueId`.
- Common: `eventKey`, `occurredAt` (ISO UTC from `createTime` via `Number()` +
  `toISOString()`), `receivedAt`, `transport`, `roomId`.
- Matching fields are ids, enums, numbers, booleans, ISO timestamps only. `giftName`,
  `nickname`, `message`, `title` are informational. Test greps `plugin/**` (minus `vendor/`)
  for `toLocale`, `Intl.`; a locale test runs the fixtures under pt_BR/America/Sao_Paulo and
  en_US/UTC and requires byte-identical output.
- Dedup: `eventKey = "tiktok:<kind>:<msgId>"`, fallbacks `…:<userId>:<createTime>` then
  `…:<receivedAtMs>:<counter>`; LRU of 4000 keys.

### Gift streaks
Tracker keyed `userId:giftId`. `giftStreakMode`: `completed` (default) emits `gift` once at
`repeatEnd` with `coins = diamondsPerGift * repeatCount`; `each` emits per tick with the
delta. Non-streakable gifts emit immediately. `gift-streak` trigger emits
`phase: progress|end`. Stale streak (15 s without ticks) is finalised with the last count.

### Session state (secret `tiktok-live-session-v1`)
`{version, sessionStartedAt, roomId, totals{coins,gifts,likes,chats,follows,shares,joins,
subscribes,peakViewers}, gifters top 20, milestones}`; in memory: full gifter Map (cap
2000), `seenUsers` for `isReturning`, per-user counters. Debounced 5 s write through a
mutation queue (LivePix `queueMutation` pattern) and on deactivate. `resetOnStreamStart`
resets when `roomId` changes.

### Battle state machine
`idle -> active -> ended`. Start on `linkMicBattle type 1` (or first `linkMicArmies` while
idle); points from `linkMicArmies`; host army = room owner id (TikFinity: first army).
Emits `battle` with `phase: start|update|lead-change|end`, `result: win|lose|draw` from the
host's perspective, `durationSeconds`. Updates throttled to 1 per 2 s. A new start while
active ends the previous one.

### Stream and connection
`stream` trigger `phase: live|ended|offline`; `connection` trigger on every state change.
`setStatus`: healthy "live: @user, N viewers", degraded "waiting for @user to go live",
error with reason (rate limit, missing username, bridge unreachable).

## Chat sending (BETA, opt-in, kill switch)

- **Default off.** Config tab "Chat (BETA)": `chatEnabled` (false), warning separator
  ("Unstable. TikTok may suspend accounts used for automated chat. Use a secondary
  account."), `chatSignInMode` select `euler-oauth` (default) | `cookies`.
- **Browser sign-in (Euler OAuth):** action `chat-sign-in` returns `authorizeUrl` and
  `expiresInSeconds`; the plugin starts a loopback HTTP listener on `127.0.0.1:<random>` with
  a `state` nonce, the user opens the URL (the Studio opens links from node outputs/README;
  the plugin cannot launch a browser), scans the QR with the TikTok app, Euler redirects to
  the loopback callback, the plugin exchanges the code and stores `access-token`,
  `refresh-token`, `expires-at` as separate vault keys (oauth-connector pattern). Refresh
  transparently; `chat-sign-out` deletes them. Triggers `chat-authorized` /
  `chat-auth-expired`.
  Open points to verify in Phase 2 against the Euler dashboard: loopback redirect URIs
  allowed; public client (no secret) or PKCE; otherwise the client secret cannot ship in
  a public ZIP and the exchange needs a tiny hosted broker (like the LivePix dashboard),
  which is a separate decision. Fallback mode `cookies`: secrets `sessionId`, `ttTargetIdc`
  pasted by the user.
- **Send:** `send-chat` requires `chatEnabled`, a valid session, an Euler key, and the kill
  switch open. Uses connector `sendMessage` (or the Euler `POST /webcast/rooms/{room_id}/chat`
  route with `x-oauth-token`). Never logs tokens.
- **Kill switch:** `chat/flags.mjs` fetches
  `https://raw.githubusercontent.com/OSC-Flow-Studio/official-community-plugins/main/plugins/tiktok-live/feature-flags.json`
  on activate and every 6 h (10 s timeout, cached in a secret, default = flags from the
  shipped `plugin/feature-flags.json`). Shape: `{ "chat": { "enabled": true, "minVersion":
  "0.1.0", "message": "" } }`. When `chat.enabled` is false: `send-chat` returns
  `{ok:false, disabledReason: "deprecated: <message>"}` without touching the network,
  `status.chatAvailable` is false, `setStatus` lists "Send chat is deprecated: <message>",
  and the node label/description already read "Send chat message (BETA, may be disabled
  remotely)". The host has no per-node deprecation UI, so this is the visible behaviour.
- Moderation actions (mute/ban/comments toggle) are **out of scope** for 0.1.0; noted as a
  follow-up since Euler scopes exist.

## Risks

- Protocol/signing breakage between releases (pinned 2.5.0); mitigated by TikFinity
  transport, `connection` trigger and status text.
- Euler anonymous rate limits; optional key; 60 s floor after 429.
- AGPL §18/§19: client use only; NOTICE shipped; repo has no LICENSE file, so the plugin's own
  license must be stated before release.
- TikTok ToS: unofficial; README says so; chat sending flagged BETA with suspension risk.
- Euler OAuth client secret cannot ship in a public ZIP unless Euler supports public
  clients/PKCE; otherwise cookies mode only or a hosted broker (decision deferred).
- One trigger per running flow: high-frequency kinds (`like`, `viewer-count`,
  `gift-streak`) belong in their own flows (documented).
